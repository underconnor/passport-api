# API 구현 순서

## 기반

Nest 부트스트랩·DB migration·healthcheck·가상 provider를 먼저 만들고 중앙 계약을 적용합니다. 운영 school/Sheets/DB 자격증명은 개발 fixture에 쓰지 않습니다. 모듈은 인터페이스로 구분하되 내부 worker까지 별도 저장소로 나누지 않습니다.

## 인증과 연결

학교 응답에서 학번을 필수로 확인합니다. 콜백의 신뢰되지 않은 입력값으로 학번 누락을 대체하지 않습니다. 학교 인증을 브라우저의 단회 시도에 묶고, 세션 발급 때 ID를 회전합니다. 재확인이 다른 학교 계정으로 기존 내부 계정을 덮어쓰지 않게 합니다.

사용자/관리자 호스트의 쿠키를 구분하고 로그인 성공만으로 admin role을 부여하지 않습니다. 관리 기능 배포 전 추가 인증과 최초 관리자 등록/복구 절차를 검증합니다.

Minecraft 연결은 검증된 사용자, 단회 link session, 프록시가 확인한 UUID/게임 세션, 웹 확인, 게임 확인을 한 트랜잭션에서 검증합니다. 링크 GET은 정보를 보여줄 뿐 연결 확정에 사용하지 않습니다.

## 명부와 정책

Sheets는 5분 polling 후보로 시작합니다. 필수 열·중복 학번·대량 삭제를 검사한 뒤 snapshot을 원자적으로 반영합니다. 마지막 검증 성공 이후 24시간을 넘는 기존 일반 회원 lease를 발급하지 않는 안을 검증합니다. 신규 회원 자동 승인은 동기화 실패 중 보류합니다.

정책 lease는 60초, 정상 회수는 중앙 DB 변경 반영 이후 5초를 목표로 합니다. outbox와 변경은 같은 transaction에 기록합니다. 알림이 유실되어도 주기적 재조회로 회복합니다. 각 수치는 아직 측정 전 초기 제안입니다.

Discord ID는 숫자 문자열 형식만 검사하고 존재·소유를 보장하지 않습니다. `self_reported` ID를 전역 unique로 잠가 타인의 학교 계정을 선점하지 않도록 하고, 중복은 수동 확인 정보로 처리합니다. 변경은 자기 웹 세션에서만 가능하며 다른 계정의 로그인/복구/권한에 영향을 주지 않습니다.

## 완료 조건

학교 로그인·시트 대조·원자적 게임 연결이 실제 클라이언트와 끝까지 작동하고, 만료/재사용/학번 불일치/중복 UUID/관리 API 우회/시트 장애/접속 중 정지에서 허가 범위를 지켜야 합니다. 빌드 성공과 실제 학교/게임 검증은 별도로 기록합니다.
