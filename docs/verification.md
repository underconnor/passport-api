# API 검증 기록

## 초기 개발 배포 — 합성 회원

2026-09-30의 초기 개발 단계 기록입니다. 아래 비활성 항목은 후속 실제 연동 단계에서 구현·검증했습니다.

- 단위·명부 파서 7개와 전용 PostgreSQL 통합 13개가 통과했습니다.
- Linux 컨테이너에서 독립 Docker build, migration, 명시적 development seed, DB health check를 확인했습니다.
- 실제 사용자 웹 프록시와 배포 API를 통해 HTTP 검사 24개를 통과했습니다. 웹 확인만으로는 접근을 허가하지 않고, 다른 게임 세션은 403, 양쪽 확인은 연결 완료, 재사용은 409를 반환했습니다.
- 배포 정책 응답은 JSON Schema에 부합했습니다. 개발 게임 서버의 실제 Java HTTP client로 정책을 조회하고 미연결 UUID가 허가되지 않는 것을 확인했습니다.
- 사용자 브라우저에서 합성 로그인, Discord ID 저장·새로고침·삭제, uint64 초과 거절, 로그아웃, 비회원의 빈 서버 목록, 관리자 접근 차단을 확인했습니다.
- 포털과 관리자 쿠키가 같은 호스트의 다른 포트에서도 분리되며 학교 토큰·서비스 비밀을 프런트에 제공하지 않습니다.

실제 u-SAINT 계정, Google Sheets 회원 반영, 관리자 MFA, 정품 Minecraft 클라이언트의 전체 접속과 서버 이동은 아직 검증하지 않았습니다. 학교 경로는 503, 관리자 작업은 403으로 닫혀 있습니다. 이 결과는 운영 인증 완료를 뜻하지 않습니다.

UI는 후속 디자인 변경과 별도로 다시 검증합니다. GitHub Actions 결과는 실행한 commit의 run 상태를 기준으로 판단합니다.

## 실제 연동 구현 검사 — 2026-09-30

- 실제 학교 로그인 화면·익명 포털 HTTP 응답을 확인했다. 실제 학교에 보낸 잘못된 토큰은 거절되었다.
- 공식 로그인 토큰 교환·SAP 쿠키·학교 렌더링 학번 대조 어댑터, 최소 정보 파서의 단위 검사를 통과했다.
- 실제 Google 명부의 필요한 두 열만 읽어 36명을 검증했고, 분리된 실제 인증 DB에 snapshot 36개를 반영했다. 재학·휴학을 모두 허용하며 학번 원문과 전화번호는 저장하지 않는다.
- 단위·파서·TOTP·암호화 검사 28개 통과. 통합 테스트 전체 명령에서 PostgreSQL HTTP/게임 14개, 명부 원자 반영 10개, 학교 세션·관리자 MFA/정책 13개로 총 37개 통과.
- 학교 HTTP 통합 테스트는 테스트 프로세스에서만 합성 학교 응답을 주입한다. 실제 Google 읽기 성공이나 파서 단위 성공을 실제 사용자 학교 로그인 완료로 계산하지 않는다.
- 학교 state·현재 브라우저 결합·만료·동시 콜백 단일 성공·토큰 재사용 차단·세션 회전·암호화 링크 복귀를 확인했다.
- 최초 운영자 단일 등록, TOTP 등록키 암호화, MFA 후 쿠키/CSRF 회전, 코드 재사용 거절, 실패 잠금, 정지·서버 제한·연결 해제·감사 actor 기록을 확인했다.
- outbox cursor의 초기 동기화·범위 초과·보관 기간 경과·DB 복원 초기화와 서비스 인증을 확인했다. 이벤트는 정책 조회를 유도하며 직접 허가하지 않는다.

## 실제 HTTPS·학교 계정 QA — 2026-09-30

- production/university 모드에서 가상 로그인 404, CSRF 없는 인증 시작 403, 익명 관리자 접근 차단을 확인했다.
- 사용자 본인이 학교 공식 화면에서 로그인한 뒤 계정 화면으로 복귀했다. 서버에서도 `identityProvider=usaint`인 Subject 1명과 `membershipStatus=active` 1명을 확인했다. 실제 학교 토큰 교환·학교 응답 학번 파싱·실제 명부 매칭이 완료되었다.
- 프록시의 콜백 URL·헤더 로깅을 제거했다. 의도적인 오류 응답에 넣은 합성 토큰·쿠키·인증 헤더 표식이 로그에 남지 않는 것도 확인했다.
- 실제 인증 DB를 native dump한 뒤 네트워크 없는 별도 PostgreSQL에 복원하고 12개 테이블의 행 수 일치를 확인했다. 이는 원격 보관 정책이나 지속 백업 자동화의 증명은 아니다.

관리자 인증 앱 등록과 정품 Minecraft 접속 왕복은 사용자 참여로 별도 확인한다. 인터넷 공개 여부와 실사용 시험 결과는 비공개 배포 기록에서 구분한다. 개인 학적 화면·학교 토큰·비밀번호는 저장소에 보관하지 않는다.

## 정책 이벤트 커밋 순서 회귀 검사 — 2026-09-30

서로 다른 회원의 정책 변경이 겹치면 작은 sequence ID가 늦게 커밋되어 소비자의 커서에서 누락될 수 있음을 확인했습니다. 이벤트를 만드는 정책 트랜잭션만 공통 advisory transaction lock을 첫 SQL로 획득하도록 변경했습니다. 인증 준비·MFA·이벤트 조회는 이 잠금을 획득하지 않습니다.

운영 데이터와 분리한 `_test` DB의 `policy_order_test` schema에서 세 연결을 사용한 실제 PostgreSQL 동시성 검사 2건을 통과했습니다.

- 첫 이벤트를 미커밋 상태로 유지하고 `pg_locks`로 두 번째 writer의 대기를 확인했습니다. 두 번째 callback·ID 발급은 첫 커밋 이후 진행되며, 두 차례 커서 조회가 각 이벤트를 빠짐없이 받았습니다.
- 첫 writer가 이벤트 생성 후 롤백하면 잠금이 해제되고 대기 writer가 커밋합니다. 롤백이 남긴 sequence gap은 소비자 reset으로 처리되며 이후 이벤트도 정상 조회됩니다.

새 schema의 migration과 회귀 파일은 기존 `npm run test:integration` 및 GitHub Actions에 포함했습니다. 테스트는 DB 이름이 `_test`로 끝나지 않으면 실행을 거부하며 실제 회원·학교 인증 데이터는 사용하지 않습니다.

학교 로그인 완료도 같은 정책 트랜잭션을 사용합니다. 기존 Minecraft 연결이 있는 신원의 학교 재인증은 유효기간 갱신과 정책 버전·이벤트를 원자적으로 반영합니다. 연결된 만료 신원을 합성 학교 응답으로 재인증하여 새 유효기간, 정책 버전 증가, 이벤트 1건 추가와 active 정책 복구를 확인했습니다.

최종 빌드, 단위·파서·TOTP 28개, PostgreSQL 통합 40개(HTTP/게임 14, 명부 10, 학교·관리자 14, 이벤트 순서 2)를 통과했습니다. 운영 DB를 변경하거나 실제 학교 토큰으로 이 회귀 검사를 수행하지 않았습니다.
