# 본인 학번과 학기별 학교 인증

학교 인증 만료는 `Asia/Seoul`의 다음 3월 1일 또는 9월 1일 00:00이라는 **배타적 경계**입니다. 2026년 10월 1일 인증의 경계는 `2027-02-28T15:00:00Z`이며, 화면에는 하루 전인 `2027년 2월 28일`을 표시합니다. 5월 인증은 8월 31일까지입니다. 개강일 00:00에 인증하면 다음 학기의 경계를 사용합니다. 날짜만 표시할 때는 반환된 경계에서 1ms를 뺀 후 한국 시간대로 포맷합니다.

`Subject.studentIdCiphertext`는 `.5` 개인정보 안내에 동의한 포털 학교 로그인에서만 기록합니다. 학교가 검증한 8–10자리 학번을 기존 `DATA_ENCRYPTION_KEY`로 AES-256-GCM 암호화하고, `student-id:<universityKey>` AAD로 계정 간 암호문 바꿔치기를 막습니다. `/v1/me.studentId`는 로그인한 본인에게만 복호화하여 반환합니다. 인가된 관리자 회원 목록 `/v1/admin/members`의 `studentId`에도 저장된 검증 학번을 반환합니다. 관리자 호스트·학교 세션·등록 관리자 인가를 먼저 확인하며 일반 사용자·서비스 Bearer로 조회할 수 없습니다. 서비스 API, 게임 정책, Discord, 감사 로그에는 원문·암호문을 반환하지 않으며 관리자 응답에도 암호문은 포함하지 않습니다. 원래 명부 대조와 관리자 전체 학번 검색에는 계속 HMAC을 사용합니다.

기존 계정은 `studentId:null`이며 HMAC·명부에서 학번을 복원하거나 추정하지 않습니다. 새 동의만으로도 채워지지 않으며 학교 로그인이 필요합니다. 관리자 로그인에는 동의 흐름이 없으므로 새 학번 암호문을 저장하지 않습니다. 이미 포털에서 동의하여 보관한 암호문은 관리자 재로그인으로 갱신하지 않습니다. 계정 삭제 시 암호문도 삭제되며 백업은 기존 보관 주기를 따릅니다. 키 회전은 TOTP·학교 연결 문맥뿐 아니라 이 암호문에도 영향을 주므로 재암호화하거나 학번 필드를 비우고 재로그인하도록 합니다.

## 배포 및 기존 계정 변환

1. 기존 암호화 백업 후 `prisma migrate deploy`로 두 nullable/default 호환 필드와 CHECK를 추가합니다. 추가 환경 변수는 없습니다.
2. 새 이미지의 `node dist/school-expiry-migrate.js --dry-run`으로 대상·변경·이미 만료된 계정 수만 확인합니다. 계정 식별값은 출력하지 않습니다.
3. `node dist/school-expiry-migrate.js --apply` 또는 API 시작 시 자동 변환을 실행합니다. `Subject.universityExpiryPolicyVersion=1`로 완료를 표시하여 재시작에도 중복 작업하지 않습니다.
4. 변환은 각 계정에 대해 기존 `universityVerifiedAt`으로 계산하며, 이미 만료된 인증은 `min(이전 만료, 새 경계)`로 유지하여 다시 활성화하지 않습니다. 인증 시각이나 만료가 없던 계정도 새 권한을 얻지 않습니다. 살아 있는 인증이라도 개강일을 지난 오래된 인증이면 즉시 만료될 수 있습니다.
5. 계정·Discord 역할 및 닉네임 만료·Minecraft 정책 버전 및 이벤트를 하나의 정책 writer lock 트랜잭션에서 갱신합니다. 기존 60초 정책 lease를 넘어 낡은 권한을 유지하지 않습니다. 만료가 같으면 버전 마킹만 합니다.
6. `--dry-run` 재실행 결과 대상 0과 정책/Discord 반영을 확인합니다. 원래 180일 규칙으로 자동 역변환하지 않습니다. 롤백은 기존 코드가 추가 필드를 무시할 수 있지만 만료 정책 자체는 별도 승인 없이 늘리지 않습니다.

새 `.5` 안내를 아직 수락하지 않았더라도 `.4`의 게임 실명·연도·활동 동의와 `.3`/`.4`의 Discord 동기화 동의는 유지합니다. 새 학교 로그인/연결은 최신 `.5`가 필요합니다. 안내 갱신은 최신 버전을 한 번 기록하며, 이전 게임 동의가 있다는 이유로 새 안내 기록을 생략하지 않습니다.

관리자 목록의 `studentId`도 암호문이 없거나 손상·계정 불일치이면 null입니다. 기존 `admissionYear`는 게임·하위 호환용 두 자리 값으로 유지하며 전체 학번을 대신 생성하지 않습니다. 관리자 목록 확장은 저장된 값을 읽기만 하므로 DB migration·추가 환경 변수·학교 로그인 갱신·관리자 등록 변경이 없습니다. 안내 `.5`의 회원 관리 목적 문구만 실제 표시 범위와 일치시킵니다.
